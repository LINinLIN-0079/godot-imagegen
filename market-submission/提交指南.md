# 提交指南：把 godot-imagegen 收录进 DSH 插件市场

> 本目录是投稿材料的**留档**，不参与插件运行，`package.json` 的 `files` 里也没有它。
> 收录与否只取决于仓库本身，与这个目录无关。

## 一、市场是什么

1. **`dsh-market` 仓库不收插件** —— 它只是市场应用（阅读器）。
2. 插件目录的唯一来源是
   [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)
   注册表：`data/plugins/<owner>__<repo>.yml`，一个插件一个文件。
3. 合并后 `dsh-market` 自动从
   [awesome-dsh-plugin.com/plugins.json](https://awesome-dsh-plugin.com/plugins.json)
   拉取，插件出现在浏览 / 搜索里。

`created_at` 是 2026-10-10T01:17:38Z，门槛在 **2026-10-11 09:17（本地）** 满足。
CI 的提示是：

> repository is 0.0 days old (needs 1) — nothing to do: this check re-runs by itself and
> should clear in about 24h. No need to resubmit, push, or close and reopen.

这不是安慰话：`.github/workflows/regate.yml` 每 6 小时（`cron: '19 */6 * * *'`）跑一次，
其中 reason 3 `aged` 专门匹配 `days old` 类失败，**并且被刻意豁免于红 check 的否决**

就是为了让「只差时间」的投稿能被时间本身解放。**所以不要重开 PR，也不要为了触发 CI 再 push。**

## 三、提交内容

**一个 YAML 文件就是全部投稿。** 两个 README 由 `data/plugins/*.yml` 生成，合并后在 `main` 上自动重新生成——
**不要手工编辑 README，也不需要提交它们**。这正是条目文件制取代「往 README 追加」的原因：
条目文件永不相撞，生成出来的 README 行总是相撞。

条目见 [`data/plugins/LINinLIN-0079__godot-imagegen.yml`](data/plugins/LINinLIN-0079__godot-imagegen.yml)。

> 描述含 `: `（冒号 + 空格）时**必须用引号包裹**，否则 YAML 会把它当成嵌套键。本条目已包裹。
> 中文全角冒号没有这个问题。

## 四、截图（可选，推荐）

**约定已变**：截图不再写进市场的 `data/screenshots.json`，而是**放在本仓库自己的
`screenshots.json`**（与 `package.json` 同级），列出 1–8 张图片路径：

```jsonc
// <本仓库>/screenshots.json —— 路径相对于该文件
[
  "assets/screenshot-1.png",
  "assets/screenshot-2.png",
  "assets/screenshot-3.png"
]
```

好处：以后换图推自己的仓库即可，不用再提 PR、不用等维护者；相对路径在改名时会立刻暴露，
而写死在市场那边的绝对 URL 只会悄无声息地烂掉（已发布的 773 张里有 41 张成了 404）。

规则：1–8 张；相对路径不得跳出插件目录（不能以 `/` 开头、不能含 `..`）；也接受 GitHub 托管的 https 绝对 URL。

**当前状态：尚未声明。** 本仓库里还没有任何图片，而声明了却指向不存在的文件会让市场卡片出坏图——
**所以必须真的有图之后再写 `screenshots.json`**。不声明不是缺陷：市场会退化为从 README 抽取图片。
